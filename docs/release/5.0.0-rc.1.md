# CosId 5.0.0-rc.1 (draft release notes)

> Draft, written with the API freeze (`docs/architecture/api-freeze.md`, #1372–#1377). Not published: the release, its
> date and the rest of these notes (performance gate, other fixes since alpha.1) are the user's call.

## The compatibility promise starts here

From RC1 on, the Java API, the `cosid.*` configuration and the storage formats and protocols are frozen: later 5.x
releases only add to them (api-freeze §0). What the promise covers:

- **Java types** ([the runtime](https://cosid.ahoo.me/guide/concepts/runtime.html#compatibility-of-the-java-types)):
  specs, options and SPI values are final classes with builders, and gain fields only with defaults equal to the former
  behavior; closed values stay records; the sealed specs may gain variants, so a `switch` over them keeps a `default`.
- **Configuration:** the `cosid.*` keys, defaults and checks. New keys come with defaults, and no check gets stricter.
- **Storage and protocol:** fields are only appended, and old readers ignore them.

Not covered: the `internal` packages, the Spring binding class `CosIdProperties` (the keys are the promise, not the
type), and meter values (names and tags are covered).

## Upgrading from 5.0.0-alpha.1

**Java API**

- The configuration and SPI value types are no longer records: `RuntimeSpec`, `StoreSpec`, `MachineSpec.Leased` /
  `Static`, `GeneratorSpec.Snowflake` / `CosId80` / `Segment` / `PeriodicSegment`, `BatchPolicy`, `PeriodicPolicy`,
  `RuntimeOptions`, `StoreConfig`, `SlotLease`, `AcquireResult.Acquired`, `GeneratorInfo`. Build them with
  `builder(...)` and change them with `toBuilder()` / `with*`; the accessors keep their names. The 8-argument
  `RuntimeOptions` constructor and `withCountGenerated` are gone.
- `IdGenerators.uncertain` throws `IdOverflowException`; a time beyond the layout throws `TimeOverflowException`; an
  epoch in the future fails the start.
- New: `GeneratorSpec.Custom` / `Instance` (a `long` generator of your own, which the runtime serves but does not own),
  `MachineSpec.Leased.acquireTimeout` (default the ttl, 0 tries once), named machines (`RuntimeSpec.Builder.machine(name,
  spec)`, `GeneratorSpec.*.machine(name)`, `CosIdRuntime.slot(name)` / `machines()`), `Leased.slotOffset`, a
  configurable cosid80 `layout` and `PartsCodecSpec.Friendly.padStart`, and `CosIdRuntime.text(name)`.
- SPI: `SlotLeaseStore.acquire` takes an `int slotOffset`; `JdbcDialect.insertNamespaceIfAbsent` takes it too and
  gains `addColumn`. A custom store forwards it and passes the TCK case `rejectsMismatchedSlotOffset`.

**Spring Boot**

- **`cosid.namespace` now defaults to `spring.application.name`** (then `cosid`, with a WARN). An alpha.1 application
  that left it unset used `cosid`; set `cosid.namespace: cosid` to keep its slots and segment keys, or the next start
  uses a new, empty namespace (segments would start again from their initial offset).
- A `cosid.*` key that binds to nothing fails the start, listed by property path (not checked: `stores.*.options.*`,
  the integration and server keys, system properties and environment variables).
- The health indicator is `cosid` (`/actuator/health/cosid`, `management.health.cosid.enabled`), and its details are
  `{machines: {<name>: {...}}}`.
- cosid-server: the backing store's readiness contributor is `cosidServerStore` (alpha.1: `cosIdServerStore`, no alias,
  D33). A `management.endpoint.health.group.readiness.include` that names it needs the new name.
- Meters: `cosid.segment.reserve` and `cosid.segment.refill.failures` lose the `key` tag; the `cosid.machine.*` meters
  gain a `machine` tag. `cosid.metrics.generated` is now `cosid.metrics.generated.enabled`.
- New keys: `cosid.machines.<name>.*` and `cosid.generators.<g>.machine`; `leased.slot-offset` and
  `leased.acquire-timeout`; cosid80 `time-bits` / `node-bits` / `seq-bits` / `seq-reset-threshold` and friendly
  `pad-start`; `strategy: custom` with `ref`. cosid80 refuses `epoch`, `unit` and the radix `width` / `pad-start`.

**Storage**

- The namespace metadata gains `slotOffset` (JDBC column `slot_offset`, Redis hash field, Mongo field, ZooKeeper line).
  alpha.1 data without it reads as 0 and is never rewritten. A JDBC table of alpha.1 gets the column from `initSchema`;
  without `initSchema`, offset 0 keeps working and a non-zero offset fails with the `alter table` statement to run.
- cosid-server: `/slots:acquire` takes an optional `slotOffset` (default 0). A named machine's namespace must be in a
  restricted token.

**Migration from 4.x**

- A CosIdGenerator with a `cosid.generator.namespace` of its own now migrates (alpha.1 refused it): the shared
  namespace is migrated once, rolling with 4.x by default, and each service gets `cosid.machines.generator`
  ([guide](https://cosid.ahoo.me/guide/migration/from-4x.html#a-shared-cosidgenerator-namespace)).
- `config` keeps the 4.x CosIdGenerator bits, threshold and friendly `pad-start`.
