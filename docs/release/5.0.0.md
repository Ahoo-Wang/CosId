## What changed since rc.1

### Spring Boot 4.1.2 and later only (#1416, D49)

- The lowest Boot supported is the build's, 4.1.2: the published metadata of `spring/*` and the integrations requires
  the versions it resolves (`spring-boot-autoconfigure` 4.1.2, `spring-data-jdbc` 4.1.2), not those of 4.0.9.
- CI tests Boot 4.1.2 on Java 21 and 25; `-PspringBootVersion` stays to probe a later Boot.

### Migration from 4.x: the two BLOCKERs of round 2 (#1415)

- **`config` writes the stores `apply` wrote to** (R2-mig-01): the type of `target` / `machineTarget` in
  `apply-result.json`, the JDBC table options, the Mongo `database`, Redis `cluster` and the ZooKeeper connect string;
  a change of store type is reported, and each migrated segment gets `initial-offset`, its migrated next value.
- **A snowflake's namespace of its own becomes a named machine** (R2-parity-01, D37), migrated once like the shared
  `cosid.generator.namespace`; `plan.json` and `apply-result.json` gain `machineNamespaces`.
- The tool checks and normalizes its store options (`range-table` is `rangeTable`; unknown keys are refused), carries
  the 4.x store options over (`wait: N`, `fetchPlan`, `writeConcern`, the Curator retry), waits for Redis Cluster
  replicas on the right connection, keeps URL passwords out of JDBC errors, and keeps the 4.x friendly text unpadded.

### Core, Spring and server (#1418)

- **The starter depends on `spring-boot-starter`**, as Spring Boot's starters do: an application with the CosId starter
  alone gets logging and YAML configuration (the published-jar smoke test found it missing).
- **`cosid-activiti` brings MyBatis 3.5.19** instead of the 3.4.2 of Activiti 7.0.0.SR1 (GHSA-qq48-m4jx-xqh8); MyBatis
  3.6 does not run Activiti 7.
- **uuidv7:** the runtime's one `UuidV7Generator` counts every id (its Spring bean too), ends with the runtime as the
  other strategies do, and a disabled one keeps its bean, which throws on use.
- **Configuration:** a key of another strategy (`period` on a `segment`) is ignored with a warning; a list replaced by a
  higher property source (a profile) is no unknown key.
- `StoreConfig` / `StoreSpec` print their options without secrets; `onBatchResized` fires for every resize; the
  describe keys of uuidv7 are listed.
- cosid-server: the JDBC pool keeps 2 idle connections, waits for one no longer than the store timeout, and has one
  per generator besides the blocking threads.
- CI: the published jars run in a Maven and a Gradle application on Boot 4.1.2 with the Redis and MongoDB stores
  (`published-jars`); P8 of the release gate goes through the runtime.

### The cosid-server image on JDK 25 (#1414, D48)

The image runs on `eclipse-temurin:25-jre`; the jars stay Java 21 bytecode. From JDK 24 on (JEP 491) a virtual thread
no longer pins its carrier inside `synchronized`, and the server runs its requests on virtual threads.

### Documentation (#1417, WP-docs-r2)

- Decisions D39–D49 in the decision table.
- uuidv7 and custom in every strategy list; the 4.x text API (`generateAsString()`) and its default radix 62 text in the
  migration guide; the 4.x proxy server keys against cosid-server's; the driver versions an application gets with Maven
  and Gradle; the JavaScript precision of `/ids`; the protocol fields of `/slots:*`; the SPI method contracts.

## Upgrading from 5.0.0-rc.1

1. **Spring Boot 4.1.2 or later.** Boot 4.0.x is no longer supported (D49).
2. **cosid-activiti:** MyBatis 3.5.19 now comes with it; an application that pins MyBatis 3.4 for Activiti keeps 3.5.19
   or later instead.
3. **The migration tool:** a 4.x snowflake with a `namespace` of its own needs that namespace migrated once on its own
   (`plan --namespace <it> --layout-config …`, then `apply`) before each service, as the shared
   `cosid.generator.namespace` does; run `config` again with the new `apply-result.json`. Store options the tool did not
   read are now refused: spell them as the store does.
4. Nothing else: no API, configuration, storage or protocol change needs you.
