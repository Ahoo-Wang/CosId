# CosId 5.0.0-rc.1

The first release candidate of CosId 5, a GitHub **pre-release** (tag `v5.0.0-rc.1`; the Docker image is not tagged
`latest`). It follows [5.0.0-alpha.1](5.0.0-alpha.1.md) and contains #1364–#1399. Production use should still wait
for GA; RC1 is for trying the release and upgrading from 4.x on staging.

第一个候选发布版(GitHub pre-release)。从 RC1 起,API、`cosid.*` 配置、存储格式与协议冻结，之后的 5.x 只做向后兼容的增量。

## The compatibility promise starts here

From RC1 on, the Java API, the `cosid.*` configuration and the storage formats and protocols are frozen: later 5.x
releases only add to them (api-freeze §0). What the promise covers:

- **Java types** ([the runtime](https://cosid.ahoo.me/guide/concepts/runtime.html#compatibility-of-the-java-types)):
  specs, options and SPI values are final classes with builders, and gain fields only with defaults equal to the former
  behavior; closed values stay records; the sealed specs may gain variants, so a `switch` over them keeps a `default`.
- **Configuration:** the `cosid.*` keys, defaults and checks. New keys come with defaults, and no check gets stricter.
- **Storage and protocol:** fields are only appended, and old readers ignore them.

Not covered: the `internal` packages (each exported package now has a `package-info` saying what it is; `internal`
is "Not API"), the Spring binding class `CosIdProperties` (the keys are the promise, not the type), and meter values
(names and tags are covered).

## What changed since alpha.1

### API freeze (#1371–#1377)

- **Value types that can grow** (#1372): `RuntimeSpec`, `StoreSpec`, `MachineSpec.Leased` / `Static`, the generator
  specs, `BatchPolicy`, `PeriodicPolicy`, `RuntimeOptions`, `StoreConfig`, `SlotLease`, `AcquireResult.Acquired` and
  `GeneratorInfo` are final classes with `builder(...)`, `toBuilder()` and `with*`.
- **cosid80 is configurable** (#1373, D36): `time-bits` / `node-bits` / `seq-bits` / `seq-reset-threshold` and the
  friendly `pad-start`; `MachineSpec.Leased.acquireTimeout`; custom `long` generators (`GeneratorSpec.Custom` /
  `Instance`, `strategy: custom`).
- **Named machines and slot offsets** (#1374, D37): `cosid.machines.<name>`, `cosid.generators.<g>.machine`,
  `leased.slot-offset`, `CosIdRuntime.slot(name)` / `machines()`, a `machine` tag on the `cosid.machine.*` meters.
- **The contracts are written down** (#1397): listener threads and failures, codec and filler failures, what a store
  provider and a store throw (any `RuntimeException`; a timeout is recognised with `StoreTimeoutException.isTimeout`),
  what `CosIdRuntime.get` returns belongs to the runtime.

### Configuration (#1375, #1378, #1397)

- **A `cosid.*` key that binds to nothing fails the start**, listed by property path. Store options are declared by
  each provider (`StoreProvider.options()`); keys match them ignoring case, `-` and `_`, and any other key fails the
  start (cosid-server's backing store too).
- **`cosid.namespace` defaults to `spring.application.name`** (then `cosid`, with a WARN) (D38).
- Namespaces, generator and machine names and keys are limited to what every backend stores (`StoreKeys`): namespace
  1–100 of `A-Z a-z 0-9 . _ : -`, keys of at most 255 UTF-16 units.
- `- friendly: {}` (an empty codec item) binds to that codec with its defaults on Spring Boot 4.0 too; an item with
  nothing in it says so.
- One INFO line when cosid-spring-data-jdbc is on the class path but `cosid.jdbc.enabled` is not `true`.

### Storage formats (#1374, #1378, #1379, #1393, #1396)

- **Namespace metadata gains `slotOffset`** (JDBC column `cosid_namespace.slot_offset`, Redis hash field, Mongo field,
  ZooKeeper line). alpha.1 data without it reads as 0 and is never rewritten.
- **JDBC:** the index `<slotTable>_last_owner_key` on `cosid_slot (namespace, last_owner_key)`, which the acquire uses
  to find its own rows; `initSchema` and the migration target add it, and the column, to tables of alpha.1. A reserve
  guards against SQL proxies that drop generated keys (`options.fetchPlan=transaction` for those that need it). The
  dialect SPI separates its operations from the SQL hooks, which may change in a minor version.
- **MongoDB:** the store no longer creates `ns_ownerKey` on `cosid_slot` (no query uses it). An alpha.1 index is
  harmless; drop it with `db.cosid_slot.dropIndex("ns_ownerKey")`.
- **Redis:** the slot row stays positional; fields are only appended, and a reader keeps the fields it does not know
  when it writes the row back (06 §2.2).
- **ZooKeeper:** a range node recreated under a store is detected (its `czxid`), and the store fails like one that
  went back instead of issuing the range. The invariant is written down: no range node is deleted while a store uses
  it; purge only with every instance stopped.

### Migration from 4.x (#1369, #1370, #1376, #1399)

- **A shared `cosid.generator.namespace` migrates to a named machine** (alpha.1 refused it): the namespace is migrated
  once, rolling with 4.x by default, and each service gets `cosid.machines.generator`.
- **Slot offset and headroom:** the shared slots go to the top of the node range (default `2^node-bits - 2^bits`),
  above the 4.x machine ids; plan.json records the headroom left to 4.x, and `guaranteed: false` when an explicit
  `--slot-offset` cannot keep 4.x and 5.0 apart by construction.
- Guardrails: `--allow-unmigrated`, `--machine-from` / `--machine-to` on `plan`, `--allow-new` on `config`, and
  `verify` reports 4.x keys that are not in the result (09 §2/§3).
- Redis writes of the migration (the 4.x seal, the 5.0 raise and prepare) wait for a replica (`WAIT 1`) when the node
  has one, and stop when none acknowledges within 5 s. Messages no longer show passwords in store URLs.
- `config` keeps the 4.x CosIdGenerator bits, threshold and friendly `pad-start`.

### Performance (#1380, #1381, #1392, #1394, #1398)

- Segment fast path, observed stores, JDBC / MySQL / MongoDB / ZooKeeper hot paths (WP-perf P1, P3).
- The release gate judges end-to-end ID generation (D44): P1–P8, P11, P12 must stay within the D34 tolerances of
  4.1.0; component rows (P9 codecs, P10 store primitives) may WARN within the D44 limits without blocking.
- A missing side or a JMH failure is a harness error, not a result; the benchmark jars carry every store's provider.

### cosid-server (#1365, #1397)

- **The backing store's readiness contributor is `cosidServerStore`** (alpha.1: `cosIdServerStore`).
- `cosid.server.docs.public` opens Swagger UI and the OpenAPI document without a token (springdoc paths only).
- Virtual threads by default; store calls stay bounded by the blocking pool.
- Client tokens reach the client paths only (default deny); a separate management port is refused unless anonymous.
- The runtime reuses the backing store instead of opening a second one.
- A token sent over plain `http` to a non-loopback host is logged as a WARN by the remote store.

### Fixes

- Segments: a caller reserves only once no ready range is left (#1391).
- Redis: what `wait` resolved to is logged once at start (restart after adding or removing replicas).
- JDBC: the unpooled data source keeps the URL password out of `toString` and the login timeout per instance.

### CI and security (#1384, #1385, #1394, #1398)

- One CI workflow with path filters, a single summary check, coverage flagged per job; time limits on every job.
- The documentation site's vulnerable dependencies are patched.
- The benchmark jars are checked on every CI run (`checkJmhJar`).

## Upgrading from 5.0.0-alpha.1

alpha.1 made no compatibility promise (D33); these are the steps that need you.

1. **Set `cosid.namespace` if you relied on the default.** alpha.1 used `cosid`; RC1 uses `spring.application.name`.
   Without `cosid.namespace: cosid`, the next start uses a new, empty namespace and segments start again from their
   initial offset.
2. **Remove `cosid.*` keys that bind to nothing**, and store options a provider does not declare: both now fail the
   start. `cosid.metrics.generated` is now `cosid.metrics.generated.enabled`.
3. **cosid80:** remove `epoch`, `unit` and the radix `width` / `pad-start`, which it refuses.
4. **Java API:** build the value types with `builder(...)` and change them with `toBuilder()` / `with*` (the accessors
   keep their names); the 8-argument `RuntimeOptions` constructor and `withCountGenerated` are gone. `IdGenerators.uncertain`
   throws `IdOverflowException`, a time beyond the layout `TimeOverflowException`, and a future epoch fails the start.
5. **A store of your own:** `SlotLeaseStore.acquire` takes an `int slotOffset`; forward it and pass the TCK case
   `rejectsMismatchedSlotOffset`. Declare your options in `StoreProvider.options()`. A JDBC dialect of your own
   implements `insertNamespaceIfAbsent` with the offset and gains `addColumn`.
6. **JDBC without `initSchema`:** add the column and the index yourself:
   `alter table cosid_namespace add column slot_offset integer not null default 0` and
   `create index cosid_slot_last_owner_key on cosid_slot (namespace, last_owner_key)` (with your table names). Without
   the column, offset 0 keeps working and a non-zero offset fails with the statement to run.
7. **MongoDB (optional):** `db.cosid_slot.dropIndex("ns_ownerKey")`.
8. **cosid-server:** a readiness group that names `cosIdServerStore` needs `cosidServerStore`; a named machine's
   namespace must be in a restricted token; a separate `management.server.port` needs anonymous mode.
9. **Health and meters:** the health indicator is `cosid` (`/actuator/health/cosid`, `management.health.cosid.enabled`)
   with `{machines: {<name>: {...}}}`; `cosid.segment.reserve` and `cosid.segment.refill.failures` lose the `key` tag.
